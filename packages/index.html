Why it exists

A small API for a surprisingly hard platform problem.

Launcher icons look like a simple UI detail, but production apps need to account for Android activity aliases, iOS system behavior, device reboots, app updates, scheduled campaigns, and integrations that rely on component state. This package brings those concerns behind a focused Dart API.

What it handles

Runtime switching

Move between pre-bundled icons on Android and iOS from one Flutter-facing API.

Scheduled changes

Activate campaign or seasonal icons for a time window, then reset automatically.

State recovery

Restore icon and component state after reboots, app updates, and Flutter engine attachment.

Protected components

Safeguard third-party SDK components such as push-notification integrations during icon changes.

OEM controls

Skip device brands whose launchers are known to handle dynamic icons unreliably.

Badge support

Read and update the application badge number on supported iOS versions.

A clear Flutter API

await DynamicAppIconChanger.setAlternateIconName(
  'IconBlue',
  relaunch: true,
);

await DynamicAppIconChanger.scheduleAlternateIcon(
  'IconHoliday',
  endAt: DateTime.now().add(const Duration(days: 7)),
);
